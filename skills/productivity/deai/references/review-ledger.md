# 审稿台账与 judge 评分

judge 不改文本，只出报告。报告按下面的顺序：四份审计、问题台账、七维评分、结论。

## 审计一：数据周全度

逐节列出"这类文稿在这里应当用数据、访谈或文献支撑的判断"，每条一行：

| 字段 | 说明 |
|---|---|
| 位置 | 节号和段落序号 |
| 判断 | 原文判断，不超过 30 字 |
| 应有证据 | 支撑这条判断该有的材料，例如客户数量及类型分布、项目周期、丢单原因、报价结构、人员配置 |
| 现有证据 | 公开资料 / 文献 / 访谈 / 内部数据 / 无 |
| 状态 | 充分 / 薄弱 / 缺失 / 可疑 |

"可疑"专门标来源不明的内容：有具体数字、比例、引语，却在资料来源和引文里都找不到出处；或者挂了受访者代码的转述，该受访者没说过。任何一条"可疑"直接判 P0。已经用【待补】标出的缺口记"缺失"，不记"可疑"。

审计结尾给出：应有证据的判断总数 N，充分数、缺失数、可疑数，数据周全度 = 充分数 / N。

如果稿件使用了作者声明过的设定材料（情景模拟、示例数据），judge 核对三条：性质只在一处统一说明，且说明完整；正文每个设定数字都能在设定文件里找到；数字和统计口径与设定一致。别处重复声明按过程泄漏（X03）计。

## 审计二：去 AI 化程度

1. 贴出 `prose_check.py --json` 的关键指标：红色词、黄色词每千字、句式命中、抽象名词每千字、防御性声明每千字、本文类自称每千字、句长标准差。
2. 逐段标注命中的模式编号（patterns.md），统计命中段落数 / 总段落数，以及出现最多的 5 个编号。
3. 摘出 5 句最像 AI 写的原句，每句说明命中哪个编号。

patterns.md 末尾"不计为命中"的情况不计。脚本通过不代表去 AI 化合格。脚本只查词和句式，最终以逐段标注为准。

## 审计三：语言风格

逐节读一遍，只看语言，不看证据。每项给原文例句和位置：

1. 语体：书面语体是否稳定，有没有口语、公文腔、营销腔、翻译腔混入。
2. 节奏：句长和句式有没有变化；有没有连续几段同一种开头、同一种段尾。
3. 用词：动词是否具体（"报出""签订""回电"优于"推进""实现""形成"）；名词能否指到具体对象；同一概念有没有换名。
4. 衔接：段与段靠内容接上，还是靠"由此""因此""此外"硬接。
5. 语气：判断强弱是否和证据相称；有没有审稿回复腔和格言式收尾。
6. 引语：引语和叙述语体是否分得清，有没有为了"像人"堆口语引语。

最后一段总评：这篇读起来像谁写的，离目标作者（例如"熟悉业务的在职 MBA 学生写的正式论文"）还差什么。

## 审计四：AIGC 检测模型

读主持人预先跑好的检测输出，贴出 mpu 超阈值段落比例和得分最高的 5 段。检测器噪声大，只作参考：与逐段标注一致的段落优先修改，不一致的在报告里说明。不要自己重跑检测模型。

## 问题台账

| 字段 | 说明 |
|---|---|
| ID | 视角字母加序号，如 A-01、B-03、C-12，同一轮内唯一 |
| Key | 跨轮跟踪用的稳定键，如 `s4.2-p3-l03` |
| 级别 | P0 / P1 / P2 |
| 视角 | A 论证主线；B 证据链；C 行文与图表 |
| 位置 | 小节、段落序号或行号，引用原文不超过 30 字 |
| 问题 | 只写问题，不写方案 |
| 为什么重要 | 一句话 |
| 解决标准 | 可验证，例如"该段不再出现否定对照句，且保留两处引文标记" |

级别：

- P0：核心论点不成立或无法评估。例如建议对不上问题，出现编造的数据或访谈，引文标记丢失，转述张冠李戴。
- P1：明显削弱可信度或可读性，有修复路径。例如整段抽象名词堆叠，防御性声明过多，推断写成事实，限定词丢失。
- P2：局部表达问题。例如个别黄色词过密、句长单调、表格缺来源注。

不要因为难改就升成 P0，也不要因为常见就降级。

## 七维评分（每项 1–10）

| 维度 | 10 分的样子 |
|---|---|
| 自然度 | 读不出模板，像目标作者写的 |
| 具体度 | 句子里有具体对象、阶段、渠道、证据，少抽象名词 |
| 论证 | 每段一个判断，依据紧跟，条件和边界清楚 |
| 忠实 | 没有新增事实，引文和限定词完整，问题与建议的对应不变 |
| 规范 | 语体正式，无口语碎句，术语统一，符合文体要求 |
| 语言风格 | 句式和节奏有变化，动词具体，衔接靠内容，语气与证据相称 |
| 数据周全 | 应有证据的判断大多有支撑，其余缺口已用【待补】标明 |

## 通过条件

- 行文通过：没有 P0，P1 不超过 2 条；前六维都不低于 8 分，自然度和忠实不低于 9 分；模式命中段落比例不超过 15%；prose_check 通过。
- 全面通过：行文通过，且数据周全度不低于 80%，没有"可疑"条目。

数据周全度只能靠补真实材料提高，改行文提高不了。judge 不能因为行文好就放宽数据要求，也不能因为缺数据压低行文分。

## 结论段

写"行文通过：是/否"和"全面通过：是/否"，再按优先级给出下一轮最该改的 5 处，写到具体段落。
