# deai

目标：文稿读起来像熟悉业务的作者写的。说得出谁在做什么、依据是什么、判断到哪一步为止。

本 skill 管的是：改长篇中英文稿时怎么不改坏事实，怎么查，怎么用独立评审迭代到停。

路径约定：`S` 是本 skill 所在的目录（这份 SKILL.md 所在的文件夹）。下文的命令都写成 `$S/...`，先把 `S` 设成这个绝对路径。

## 护栏

任何一步都不能违反。

1. 不编造。不新增原文和资料里没有的数据、客户、引语、时间、比例。缺材料的地方写 `【待补：具体要什么】`。judge 说缺证据时，把判断缩到资料能撑住的范围，或者删掉。不为满足 judge 补数字。
2. 先记事实账本再动笔。改一段之前记下：数字、限定词（仅、部分、约、尚未、可能、未必、如果）、判断方向、实体、条件、引文标记及其支撑的句子。改完逐项比对。
3. 限定强度跟着证据走。证据不足时保住限定词：不把"可能"改成"会"，不把"部分客户"改成"客户"，不把"影响"改成"决定"，也不靠写顺掩盖。真实材料（访谈原话、内部数据、用户提供的文件）能直接支撑的判断，就去掉"可能""推断""估算""资料未说明"这类假设性措辞，直接陈述并注明出处；材料里本来就有的数据要补上，不写成缺口。只保留材料自带的限定（受访者原话里的"可能"、预测值）。这类有意去限定的改动，不受 `--baseline` 限定词计数的约束。
4. 术语锁定。改写前建术语表（模板 `$S/templates/terms.md`），一个概念全文一个名字，不做同义轮换。
5. 最小干预。没命中问题的段落原样保留。问题编号、问题与建议的对应、表号图号、引文标记不动。
6. 正文防火墙。写作过程、资料获取、审稿要求不进正文。资料边界只在方法小节说一次。
7. 归属准确。挂了受访者代码或出处的转述，必须是那个来源说过的。作者自己的推断写成推断。

## 单遍改写流程

适合一段到一章的改写。按顺序做，不跳步。

### 1. 定位

查 `$S/references/genre-matrix.md`，按文本类型确定改写强度和要注入的具体内容。读项目已有的写作方案、术语表、资料来源。

### 2. 扫描标注

```bash
python3 $S/scripts/prose_check.py FILE.md            # 规则扫描
cp FILE.md /tmp/FILE.orig.md                          # 留原稿做基线
```

逐段对照 `references/patterns.md` 标出模式编号，对照 `references/blacklist.md` 标出命中词。每段写一句旁注，说明这段的作用：

- 旁注写不出来，这段可以删。
- 旁注里有两个以上动作，这段要拆。
- 相邻两段旁注重复，合并。

没有命中的段落标"保留"。

### 3. 四层改写

按这个顺序，技法见 `references/techniques.md`（E1 至 E14）：

1. 论证层：主张是否超出证据，观察和解释是否混在一起，比较对象是否清楚，限定语是否缺失。
2. 段落层：首句直接给本段结论；证据紧跟主张；用上一段的结论引出下一段。
3. 句子层：拆高密度句，给建议找执行者，否定对照改直接陈述，删金句。
4. 格式层：术语、标点、引号、表题、来源注。

读者嫌"太 AI"时，先补回对象、范围、边界，再调语序，最后收紧判断。不要继续删词压缩。

### 4. 自检

```bash
python3 $S/scripts/prose_check.py FILE.md --baseline /tmp/FILE.orig.md
$S/scripts/aigc FILE.md
```

- prose_check 非零必须处理，或者在交付说明里写明为什么保留。英文稿它会报"规则扫描跳过"，这不算通过：英文稿靠检测器和 judge，限定词照样用 `--baseline` 比对（含 may、might、if、some 等英文限定词），篇幅按词数算。
- `--baseline` 报限定词变少时逐处核对；同义替换、句子合并造成的计数变化可以保留，但要写明。
- 篇幅变化看输出里的"篇幅"一行。
- 逐项核对事实账本。

交付说明三部分：命中了哪些模式、怎么改的；改写文本（直接写回文件）；自检表（未新增信息、引文标记数一致、编号对应未变、字数变化、新增的【待补】清单）。

只改有问题的段落，改好就停。

## 脚本

| 脚本 | 作用 |
|---|---|
| `prose_check.py FILE [--json] [--baseline ORIG] [--lexicon EXTRA.md] [--no-sd]`（.md、.txt、.docx） | 红色词、黄色词密度、句式正则、抽象名词、防御性声明、本文类自称、列表行和加粗、破折号、句长标准差、连续等长句、限定词基线比对、汉字数 |
| `aigc FILE [--lang auto\|zh\|en] [--json] [--all-paragraphs]` | 本地 MPU 检测器逐段打分，包装 `aigc_detect.py`。按语言自动选检测器，支持 .md、.txt、.docx |
| `run_judges.sh TAG FILE OUTDIR [AIGC.txt\|auto] [SOURCES]` | 两个 judge 并行评审 |
| `render_prompt.py TEMPLATE KEY=VALUE...` | 填模板占位符 |

项目专属的空词（本稿反复出现、能换成具体动作的抽象名词）写进项目词表，用 `--lexicon` 追加，不改 skill 自带的 blacklist。

## 检测器

细节见 `references/aigc-detector.md`。

- 解释器：先找 `$AIGC_PY`，再找 `~/.cache/deai/venv`。都没有时 `aigc` 会打印建环境的两条命令，照着跑一次。脚本默认离线运行，首次必须加 `AIGC_ONLINE=1` 下载权重；忘了加时它会打印这条命令。
- 看整篇 mpu 超阈值段落比例，不看单段。ChatGPT 之前的人写 MBA 论文 18% 至 44%，代理初稿 70% 至 90%。
- 参照目标 ≤10%。这是口味参照，不是目标本身。分数应当靠补具体对象和真实材料降下来，不靠同义替换和口语化。
- 语言路由：`--lang auto`（默认）按汉字占比判断。中文用 mpu + mpu-short；英文用 desklib + mpu-en。也可以用 `--lang` 手动指定。
- 英文看 desklib 段均分：人写求职信范例多在 0.2 至 0.5，AI 稿 0.6 至 1.0。mpu-en 对正式英文误报高，只作第二意见。详见参考文件。
- prose_check.py 只扫中文。英文稿靠检测器和 judge。不套用 unslop 规则，除非用户明确要求。

## judge 迭代循环

### 什么时候用

一章以上、要交给老师或评审的正式稿，单遍改写之后还嫌 AI 味重，或者需要一份可追踪的问题台账时。短文、聊天回复不用。

### 一轮

1. 主持人（你）先跑检测器，再起两个独立 judge 并行评审。在项目根目录运行：

   ```bash
   $S/scripts/run_judges.sh ch04-r1 chapters/04.md review/loop auto "data/访谈.txt,data/digest.md"
   ```

   codex（`-s read-only` 沙箱）和 claude（`--tools` 只给读工具，`dontAsk` 拒绝未预先批准的命令，不加载 MCP）各出一份报告：`review/loop/ch04-r1-codex.md`、`ch04-r1-claude.md`。模型用各自 CLI 的默认值，`CODEX_MODEL`、`CLAUDE_MODEL` 可覆盖。报告格式和评分标准见 `references/review-ledger.md`：数据周全度、去 AI 化程度、语言风格、AIGC 四份审计，A/B/C 三视角的 P0 至 P2 台账，七维评分，通过结论。默认跑本机装了的那几个；只想跑一个时设 `JUDGES=claude` 或 `JUDGES=codex`。两个不同来源的模型盲点不同，能跑两个就跑两个。
2. 每个文件起一个 fix agent。用模板生成提示词：

   ```bash
   python3 $S/scripts/render_prompt.py $S/templates/fix-prompt.md \
     CURRENT=chapters/04.md \
     REPORTS="review/loop/ch04-r1-codex.md, review/loop/ch04-r1-claude.md" \
     SOURCES="data/访谈.txt,data/digest.md" PROJECT_RULES="plan/plan.md, prose/terms.md"
   ```

   把输出交给一个 Agent（多个文件就并行起多个）。fix agent 读两份报告，按资料核对每条意见，修全部 P0、P1 和两份报告的"最该改的 5 处"，篇幅控制在起始字数 ±3%，跑完 prose_check 和检测器后汇报。judge 错了可以拒绝，但要写理由。
3. 改前备份一份，下一轮 judge 和 `--baseline` 都用得上。
4. 并行改了多个文件后，做一次跨文件一致性核对：数字、问题定义、交叉引用、岗位名、术语。

### 模型分工

- 改写交给 fix agent，主会话只做计划、核对和协调。主会话自己动手改，就成了自己评自己改的稿。
- judge 和 fix agent 用不同的模型更好；用户指定了改写或评审用哪个模型时照办。

### 停止规则

- P0 必须清零。
- P0 为零之后，两个 judge 的 P1 条数和七维评分连续两轮不再下降，就停。judge 被要求"宁可多报"，P1 不会归零。
- 两个 judge 的数字常差很多，看趋势和交集。
- "全面通过"取决于数据周全度，改行文提高不了。缺的是材料就停下来向作者要材料。
- 每两三轮之后，加一轮整章通读，只查连贯：段与段的承接、章首对上一章结论的交代、证据之间的推理。judge 的模式计数会把推理连接词也当成 AI 痕迹，只看计数会把论证删断。见 references/lessons.md "矫枉过正"一节。

## 经验

完整清单见 `references/lessons.md`。最常见的几条：

- 修复会造出新模板。改完数一遍新句式，同一种引出句全篇最多 2 次。
- 口语不等于自然。"有它的道理""情况就变了"这类聊天口吻会被判 P1。目标是正式书面语。
- 限定词最容易在"写顺"时丢。每轮跑 `--baseline`。
- 压缩篇幅的那一轮最容易把作者推断挂到受访者名下、删掉引文标记。压缩后专门跑一轮忠实度检查。
- 设定材料（情景模拟、示例数据）的性质只在一处说明一次，如实写生成方式。
- 加字会带来新的 P1。优先删过度、重复、越出证据的句子。
- 只剩理论复述、不挂具体对象的段落最像 AI，给每个理论判断接一个具体对象。
- judge 的限定词差额计数有噪声，逐句核对后再改。
