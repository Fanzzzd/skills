# Scope

These are skills I use on my own projects every week. Ideas are welcome and each one is judged against the bar below. Questions and open-ended discussion go to [GitHub Discussions](https://github.com/Fanzzzd/skills/discussions).

## The bar

An issue stays open if it clears both parts:

1. **Observed failure.** It describes a real session: what you ran, what the skill did, what you expected. "It would be better if" does not clear this part.
2. **Fits the skill.** It does not match anything in [`.out-of-scope/`](./.out-of-scope/), and it is not a config option or a tweak for one person's workflow. Those belong in your own `CLAUDE.md` or `AGENTS.md`, or in a fork.

The size of the change does not matter. A one-word fix and a rewrite face the same bar.

## By bucket

- **`engineering/`, `productivity/`, `in-progress/`**: the bar above.
- **New skills**: proposals are closed. See [`new-skills.md`](./.out-of-scope/new-skills.md).

## Already decided

Each file in [`.out-of-scope/`](./.out-of-scope/) records one rejected idea and why. Read them before filing:

- [`new-skills.md`](./.out-of-scope/new-skills.md)
- [`judge-that-edits.md`](./.out-of-scope/judge-that-edits.md)
- [`persistent-judge.md`](./.out-of-scope/persistent-judge.md)

## Unclear issues

An issue that can't be judged against the bar gets one round of questions and the `needs-info` label. With no reply in 14 days it is closed.
